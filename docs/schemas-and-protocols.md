# Schemas & Protocols

Every important ToolTrace Bench artifact carries: schema/protocol version,
producer version, UTC timestamp, deterministic ID/fingerprint, provenance,
checksum, privacy state and verification/trust state. This page is the index;
the JSON Schemas live in [`schemas/`](../schemas/).

## Artifact inventory

| Artifact | Version source | Notes |
|---|---|---|
| Task definition (v1) | `schemas/task.schema.json` | still readable; migrated on load |
| Task definition (v2) | `tooltrace/tasks/v2.py` (`TaskDefinitionV2`) | domain, seed, side effects, scoring contract, HITL/dual-control/multi-agent/checkpoints, contamination |
| Provenance manifest | task pack metadata | fixture origin, license, creation method, source revision, integrity hashes |
| Pack index | semver + compatibility ranges | continuously versioned; generated, never hand-duplicated |
| Suite manifest / sampling selection | suite manifest schema | recorded selection manifest for every sampled subset |
| Trace | `schemas/trace.schema.json` (versioned JSONL) | migrations ship with backwards-compatible readers |

| Result bundle | `schemas/result.schema.json`, `schemas/bundle-manifest.schema.json` | SHA-256 checksums over all members |
| Experiment manifest | `tooltrace/executors/experiment.py` | pins suite/adapter/model/sampling/sandbox/scoring versions |
| Dataset snapshot | generated by `tooltrace snapshot` | changelogs, counts, hashes, reproducible indexes |

## Compatibility keys

## Trace invariants a per-line schema cannot express

`schemas/trace.schema.json` validates one event at a time, so it cannot state
anything about a stream. Two rules hold across a whole `trace.jsonl` and are
enforced by `tests/test_trace_seq_is_unique.py` instead:

- **`seq` is unique within one trace, and strictly increasing from 1.** The
  runner and the tool executor share a single `SeqCounter`
  (`tooltrace/tools/executor.py`). They previously kept separate counters, and
  every shipped bundle carried duplicate sequence numbers.
- **`seq` is the partition key for partial replay.** `replay_from_checkpoint`
  splits on `e.seq >= checkpoint_seq`, which is only meaningful while the first
  rule holds.

`tooltrace.core.versions.compatibility_key()` derives a string such as
`protocol=1;trace=1;result=1`. Comparisons, showdowns, regression baselines
and leaderboards **reject incompatible cohorts** instead of mixing them.

## Migration & invalidation rules

- New readers accept old artifacts. A frozen bundle is committed at
  `tests/fixtures/bundles/v1-frozen.tooltrace/` and
  `tests/test_bundle_schema_enforcement.py` reads it with today's readers, so
  this is a checked claim rather than an assertion. (Until that fixture existed
  every bundle test wrote a bundle with the current code and read it straight
  back, which tests a round trip, not compatibility with anything older.)
- `result.json`, `trace.jsonl` and `manifest.json` are validated against
  `schemas/` when a bundle is written, so an artifact that does not match the
  published format never reaches disk.
- Flawed published results are marked with invalidation/supersession records
  rather than silently deleted.
- Canonical indexes are regenerated from bundles — manual duplication of
  counts/tables in docs is treated as drift and fails the generated-data CI
  check.

## Verification commands

```bash
python -m json.tool schemas/task.schema.json      # all schemas parse
tooltrace validate --path tooltrace/tasks/packs   # packs against schemas
tooltrace snapshot --source results --output data/snapshots/index.json --verify
tooltrace reproduce runs/<bundle>.tooltrace       # bundle hash verification
```
